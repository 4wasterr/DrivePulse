Fleet profiles now include a unique fleet code, profile photo, registration expiry and insurance expiry. Codes are generated as CAR-XXXXXXXX when omitted. Manually assigned codes and plates are checked without punctuation or case differences, including archived vehicles. Identifier reservations in fleet_records prevent concurrent duplicate assignments. Multiple units of the same model are supported.

The shared brand/model catalog and category defaults live in shared/vehicleCatalog.json. Selecting a category suggests seating and tank capacity; staff can adjust them for the actual vehicle. Fleet photos are stored durably in the existing documents table, accept JPG/PNG/WebP up to 4 MB, and are checked by MIME and file signature. Only attached vehicle photos are public. Renter identity documents retain their existing access restrictions.

Renewal notices are computed on every notification refresh using Asia/Manila calendar dates. The bands are 16–30 days, 8–15 days, 0–7 days and overdue. Entering a new band creates a new unread notice. Updating an expiry removes its old notice. No scheduler or new database migration is required. The UI refreshes automatically every 30 seconds and on window focus. Missing dates display as “Not recorded” until staff enter them.

The existing manager role is the application's Admin / Operations Manager role. Other roles cannot edit profiles through either the profile endpoint or user-management endpoint. Clients can view their profile and contact an Admin for changes. Admins can update names, emails and roles, reset passwords, and view Active, Archived and History records. Role/email changes and password resets revoke the affected user's active sessions. Password creation and resets require 8–128 characters, uppercase, lowercase and a non-whitespace special character. Existing credentials can still be used to sign in.

The shared notification center shows renewals, Security Deposit payment/release updates and system alerts. Clients receive updates only for their own bookings; mechanics receive operational notices without payment details; security audit alerts remain Admin-only. Read state is stored per user in fleet_records and survives reloads.

Shared table/list components limit displayed records to ten per page; the audit endpoint also caps results at ten. Filters and changed result sets reset pagination. CSV export controls have been removed, and analytics date controls apply the selected dashboard period. Cancellation payment returns retain their separate accounting allocation internally. New Security Deposit labels are used throughout booking and receipt screens. Historical issued documents remain immutable.

Sidebars have fixed viewport height and hidden container overflow. Navigation can scroll independently within available space on short displays, while Log Out stays visible at the bottom. Decorative sidebar cards collapse on shorter viewports.
