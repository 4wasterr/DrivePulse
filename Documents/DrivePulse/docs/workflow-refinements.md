Mechanic inspections use the five non-overlapping checks in shared/inspectionChecklist.json. The sequence is Vehicle details → Vehicle condition → Damage status → Dispatch decision. Readings and condition fields start blank; each checkpoint requires an individual 1–4 rating (1 Good, 2 Fair, 3 Damaged, 4 Needs Repair). The final dispatch decision starts blank, and ratings 3–4 cannot receive dispatch approval. The signed-in mechanic's name and account ID are recorded with the ratings. Changing vehicle, inspection type or reservation returns to Vehicle details; Back preserves the entered readings and ratings. The final footer saves the inspection and explicit decision. The former bulk clearance API rejects requests, and reports retain the vehicle's model, fleet code and plate as a historical snapshot.

Work orders have a readable WO code, mechanic attribution, logged dates and ten-record pages. Active Work Orders, Completed / Repaired and Archived views share search and inclusive date filters based on Philippine Standard Time. Only completed work can be archived. Archive and restore require the current version, preserve invoices and costs, and leave inspection clearance holds unchanged. Both actions are recorded in audit history.

Opening client checkout prepares the Rental Terms & Agreement from the authenticated profile, selected vehicle and dates, current server rate and full existing rental terms. The review appears before final submission. Its digest is rechecked on submission to detect a changed rate, vehicle identification, profile or schedule. A stale review requires renewed consent. Preview preparation does not create bookings or issued documents.

Both online and walk-in reservation creation issue an immutable Booking Confirmation alongside the rental agreement. The confirmation modal shows the complete terms, assigned fleet code and plate, schedule, renter and rate breakdown. Print / Save as PDF opens the protected printable document in a new tab; downloading preserves the issued HTML confirmation. Confirmations remain accessible from booking and document records. Booking receipt remains distinct from approval for vehicle release.

Availability calendars clamp navigation and date entry to today or later in Asia/Manila. Same-day scheduling selects a future time, and the API continues rejecting past pick-up timestamps. Calendar columns match the selected seven- or fourteen-day range.

Find a Ride uses one column below 768 pixels, two from 768 pixels, and three from 1024 pixels. Images share a 16:10 aspect ratio, and card specifications and rates align at the base. Category, brand, price and search controls wrap without horizontal overflow. Fleet, booking, payment and document views retain ten-record pagination. Client help widgets and internal customer-support navigation have been removed; historical support data remains preserved on the server.

The public home is shared by all four roles. Workspaces and How it works remain public sections, and one sign-in page routes accounts to the client, booking agent, mechanic or operations manager workspace. Signed-in visitors see My workspace / Open my workspace links for their assigned role. Rental search and booking actions live inside the client portal. Public registration is explicitly labeled Create a client account; staff accounts are provisioned by the Admin. The landing page and authentication copy, browser title and metadata describe the shared system.
